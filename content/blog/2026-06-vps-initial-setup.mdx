> 结论先说：新 VPS 不要急着装业务。先完成 SSH 密钥登录、禁 root 密码、防火墙与 Fail2Ban，再装 Docker；暴露服务前先验证访问控制和恢复路径。

## 前言

买 VPS 之后第一时间就 `ssh root@ip` 开始装东西？别急。公网 SSH 服务会持续面对自动化探测；风险取决于认证方式、补丁状态、网络暴露面和监控响应，不能用固定存活时长概括。

以下是我每台新服务器的标配配置步骤。

## 1. 更新系统

```bash
apt update && apt upgrade -y
apt autoremove -y
```

## 2. 创建普通用户并提权

```bash
# 创建用户
adduser deploy

# 加入 sudo 组
usermod -aG sudo deploy

# 验证
su - deploy
sudo whoami  # 应该输出 root
```

**原则**：永远不要直接用 root 日常操作。

## 3. SSH 密钥登录（禁用密码）

```bash
# 在本地机器（非服务器）上执行
ssh-keygen -t ed25519 -f ~/.ssh/vps -C "vps-deploy"

# 把公钥传到服务器
ssh-copy-id -i ~/.ssh/vps.pub deploy@server_ip
```

登录到服务器，编辑 `/etc/ssh/sshd_config`：

```bash
sudo nano /etc/ssh/sshd_config
```

确保以下配置：

```
Port 22                     # 如果更换端口，记得防火墙同时放行
PermitRootLogin no          # 禁止 root 登录
PasswordAuthentication no   # 禁用密码登录
PubkeyAuthentication yes    # 允许密钥登录
MaxAuthTries 3              # 最大认证尝试次数
ClientAliveInterval 120     # 客户端超时（秒）
ClientAliveCountMax 3       # 超时重试次数
```

重启 SSH 服务：

```bash
sudo systemctl restart sshd
```

**端口选择**：改 SSH 端口只能减少部分低质量扫描噪声，不是访问控制或加固的替代品。若确需更改，先在云厂商防火墙与主机防火墙同时放行新端口，保持现有会话，用第二个会话验证新端口登录成功后再关闭旧入口。

## 4. 配置 UFW 防火墙

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing

# SSH（如果你改了端口，这里也要改）
sudo ufw allow 22/tcp

# HTTP/HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Docker 发布端口可能通过其防火墙规则绕过 UFW 预期；不要仅凭 `ufw status` 判断容器端口是否暴露。
# 在云厂商防火墙和主机规则中逐项核对发布端口；按 Docker 官方防火墙说明配置过滤。

sudo ufw enable
sudo ufw status verbose
```

## 5. 安装 Fail2Ban

```bash
sudo apt install -y fail2ban
```

创建 `/etc/fail2ban/jail.local`：

```ini
[DEFAULT]
bantime = 3600        # 封禁 1 小时
findtime = 600        # 检测窗口 10 分钟
maxretry = 5          # 失败 5 次封禁

[sshd]
enabled = true
port = 22             # 如果你改了 SSH 端口，这里要同步改
```

启动服务：

```bash
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# 查看封禁状态
sudo fail2ban-client status sshd
```

## 6. 配置自动安全更新

```bash
sudo apt install -y unattended-upgrades

# 配置
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

确认配置文件 `/etc/apt/apt.conf.d/50unattended-upgrades`：

```conf
Unattended-Upgrade::Allowed-Origins {
    "${distro_id}:${distro_codename}-security";
    "${distro_id}:${distro_codename}-updates";
};
Unattended-Upgrade::AutoFixInterruptedDpkg "true";
Unattended-Upgrade::Remove-Unused-Dependency "true";
Unattended-Upgrade::Automatic-Reboot "false";
```

安全更新会自动安装，不会自动重启。

## 7. 安装 Docker

安全底座就绪后，再装容器运行时。完整多阶段构建与 Compose 编排见 [[docker-deploy-guide|Docker 部署实战]]。

```bash
# 安装前先阅读并审阅官方脚本内容；不要在不了解影响时直接以 root 执行远程脚本。
curl -fsSL https://get.docker.com -o get-docker.sh
less get-docker.sh
sudo sh get-docker.sh

# docker 组成员通常可获得宿主机 root 级控制能力；仅对可信且确需管理 Docker 的账号授权。
sudo usermod -aG docker $USER

# 重启会话后验证
docker --version
docker compose version
```

## 8. 安装运维监控工具

基础工具：

```bash
# htop — 资源占用实时查看
sudo apt install -y htop

# btop — 更美观的替代品
sudo apt install -y btop

# ncdu — 磁盘空间分析
sudo apt install -y ncdu

# netstat — 网络连接查看
sudo apt install -y net-tools

# iotop — 磁盘 IO 监控
sudo apt install -y iotop
```

可按暴露面和维护能力选择监控方案。若部署 Netdata，先审阅安装方式与采集/上报设置，并限制其 Web 端口只对可信网络开放；不要默认把管理面暴露到公网：

先下载并审阅官方安装脚本，再按当前官方安装指南选择参数后人工执行；不要直接通过管道或进程替换运行远程内容：

```bash
curl -fsSL https://my-netdata.io/kickstart.sh -o netdata-kickstart.sh
less netdata-kickstart.sh
# 确认脚本内容、版本和采集/上报选项后，再按官方文档执行：
bash netdata-kickstart.sh
```

脚本来自外部网络，执行前应核对下载地址、HTTPS 证书和当前官方安装说明；不需要时删除本地脚本。

默认 Web 面板端口为 19999；部署后应通过防火墙、反向代理认证或私有网络限制访问，并核对当前版本的官方安全部署指南。

## 9. 配置时间同步

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo apt install -y chrony
sudo systemctl enable chrony
sudo systemctl start chrony
sudo timedatectl status
```

## 10. 系统级调优（按需）

不要把较大的文件描述符上限或 BBR 配置作为所有 VPS 的必做项。先确认服务进程的实际限制、内核支持与网络环境，再为具体服务设置并验证。以下仅为配置示例：

**调整文件描述符限制**——编辑 `/etc/security/limits.conf`：

```
* soft nofile 65535
* hard nofile 65535
```

**开启 BBR 拥塞控制**——编辑 `/etc/sysctl.conf`：

```conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
```

生效：

```bash
sudo sysctl -p

# 验证
sysctl net.ipv4.tcp_congestion_control
# 输出：net.ipv4.tcp_congestion_control = bbr
```

## 初始化预检脚本

不要把创建用户、修改 SSH、启用防火墙和安装远程脚本塞进一个“一键执行”脚本：任何一步出错都可能让当前会话断开，且不同发行版的默认端口、服务名和包名并不一致。下面的脚本只适用于使用 `apt` 和 `systemd` 的 Debian/Ubuntu，执行低风险的更新与工具安装，并输出需要人工确认的检查项；它不会修改 SSH 配置、启用 UFW 或执行远程安装脚本。

```bash
#!/usr/bin/env bash
# Debian/Ubuntu VPS 预检脚本；不会启用防火墙或修改 SSH

set -e

if [[ "$(id -u)" -ne 0 ]]; then
  echo "请以 root 或 sudo bash 运行此脚本"
  exit 1
fi

if ! command -v apt-get >/dev/null || ! command -v systemctl >/dev/null; then
  echo "仅支持带 apt-get 和 systemd 的 Debian/Ubuntu 系统"
  exit 1
fi

echo "=== 更新系统并安装基础工具 ==="
apt update && apt upgrade -y
apt install -y curl wget git ufw fail2ban htop btop ncdu \
  net-tools chrony unattended-upgrades

echo "=== 只读检查 ==="
ufw status verbose || true
ss -lntup || true
systemctl is-active ssh 2>/dev/null || systemctl is-active sshd 2>/dev/null || true
systemctl is-active fail2ban 2>/dev/null || true

cat <<'NOTICE'
=== 需要人工确认的后续步骤 ===
1. 先在第二个 SSH 会话用 deploy 用户验证密钥登录和 sudo，再修改 sshd_config。
2. 根据云厂商防火墙和实际监听端口，人工执行 ufw allow 规则；确认 SSH 规则后再执行 ufw enable。
3. 按“安装 Docker”章节下载并审阅官方安装脚本，确认内容后再本地执行；不要使用 curl|sh。
4. 根据发行版服务名确认 chrony、fail2ban 状态，并安排维护窗口处理重启。
NOTICE
```

保存为 `vps-preflight.sh`，确认系统符合前置条件后执行 `sudo bash vps-preflight.sh`。脚本成功只代表预检完成，不代表 SSH、防火墙或 Docker 已完成配置。

## 总结

安全配置不是一劳永逸的事。完成上述步骤后，仍需结合云厂商防火墙、实际监听端口、日志和恢复演练持续验证；本文没有足够的测量数据支持对“比多少裸机更安全”作百分比结论。

定期做的事：

- 每月检查一次 `fail2ban` 状态
- `apt update` 保持系统更新
- 检查 `/var/log/auth.log` 看有没有异常登录尝试
