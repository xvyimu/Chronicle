# ADR-0007 · 内容站工作台化重构基线

- **状态**：Accepted（2026-10-06）
- **决策**：在保留 Next 16 + React 19 + Tailwind v4 栈的前提下，把 Chronicle 从「Paper Gallery 暖色调传统博客」重构为「中性灰 AI 工作台气质内容站」。
- **关联**：`docs/PROJECT.md`（形态与栈 SSOT）· `docs/01-project-audit.md` · `docs/14-decision-log.md`（D-001…D-008）

---

## 背景

Chronicle 是 20 篇文章的个人博客 + 作品集。此前一轮精简已删除评论（Giscus）、数字花园、收藏导航。用户进一步要求把它改造成具有 AI 工作台视觉语言的内容工作台——但**仍然是博客，不是聊天软件**。

约束：

- 不换栈（Next 16 / React 19 / Tailwind v4）。
- 不改文章 slug；不破坏 SEO / CSP / 内容快照。
- 渐进式重构，不一次性推翻。
- 不引入账号 / 数据库 / AI 服务 / 付费服务。

## 可选方案

| 方案                                | 说明                     | 结果                             |
| ----------------------------------- | ------------------------ | -------------------------------- |
| A 整站换栈（Astro / Remix…）        | 重做内容模型与安全模型   | **否决**：无结构性问题，代价过大 |
| B 保留栈，重写内部实现 + 视觉重设计 | 换设计语言与布局，栈不变 | **采纳**                         |
| C 只清理，不改视觉                  | 保持 Paper Gallery       | 否决：不满足用户目标             |

## 决策

采纳 **B**：

1. 设计语言从「暖纸色 Paper Gallery」改为「中性灰 AI 工作台」，Token 渐进迁移（旧变量保留为兼容别名）。
2. 信息架构工作台化：TopBar + Sidebar + MainPanel 应用外壳。
3. 搜索以**客户端轻量方案**回归（20 篇规模，不恢复服务端 `/api/search`）。
4. 全站文档体系（`docs/01`–`15` + iterations + adr）。

## 影响

- `docs/PROJECT.md` 的「形态与栈」**不变**（仍 Next + React 阅读站）。
- ADR-0006（Keep Fuse search）的**实现形态变化**：不再走服务端 `/api/search`；Fuse 若用于客户端搜索则保留依赖，否则移除。**待迭代 03 定案后更新 0006 状态**。
- 新增 `docs/01`–`15` 文档层。
- 逐迭代落地，分支 `feature/architecture-rebuild-2026-10-06`。

## 后果

- 正面：满足产品目标；栈稳定；可回滚。
- 负面：视觉大改有回归风险（R1）；花园文章 wikilink 渲染待决策（R2）；快照需重生成（R3）。
